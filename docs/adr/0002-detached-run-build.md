# ADR 0002: Run / Build 采用分离式终端启动，不采集退出码

- 状态：Accepted（2026-08-25 Grilling Session 决策 D4）
- 决策者：项目负责人 + 执行 Agent

## 背景

Run / Build 需要在项目目录下执行用户配置的任意命令（`pnpm dev`、`cargo build`、自定义 `.bat` 等）。备选方案：

1. 应用内嵌终端模拟器 —— 明确禁止（MVP 硬边界）。
2. 后台子进程 + 捕获输出与退出码 —— 需要处理 shell 差异、编码、长驻进程（dev server 永不退出）与输出管道，复杂且脆弱。
3. 分离式启动到系统终端 —— 用户在真实终端中看到完整实时输出，应用不参与命令生命周期。

## 决策

- detached 启动：优先 `wt.exe`（Windows Terminal），探测失败回退 `powershell -NoExit`。
- `cwd = project.path`；启动后应用立即返回，**只报告启动动作的成功 / 失败**，不采集命令退出码与输出。
- 命令为空时按钮禁用，显示 `Run command not configured` / `Build command not configured`。

## 权衡与后果

**收益**

- 实现极小：一次进程拉起，无管道、无编码处理、无僵尸进程管理。
- 用户体验直接：输出、交互、中断都在真实终端里，与手动开发流程一致。
- dev server 这类长驻命令天然可用（`-NoExit` 保持终端不关）。

**代价**

- 应用无法知道命令真实结果；"Run / Build 失败"的验收语义收窄为**启动动作失败**（无效路径 / 终端拉起失败），命令本身执行失败不属于应用缺陷。
- 依赖外部终端可用性；`wt.exe` 缺失时回退路径必须测试覆盖。

**替代方案被拒原因**：内嵌终端违反硬边界；捕获退出码对 dev server 类命令语义不成立，且带来的复杂度与 MVP 目标（小巧、可靠）不符。
