# ADR 0003: 主题系统采用 data-theme + CSS 变量，默认跟随系统

- 状态：Accepted（2026-08-25 Grilling Session 决策 D1）
- 决策者：项目负责人 + 执行 Agent

## 背景

应用需要亮 / 暗 / 跟随系统三种主题行为、可配置强调色，且受硬约束：

- 不引入任何样式框架或 UI 库（D11）。
- 未来要能扩展主题预设（更多配色），且不改变切换机制。

备选：CSS 预处理器方案、CSS-in-JS、组件级内联样式、纯 CSS 变量。

## 决策

- 单一全局样式表；颜色、间距、圆角、状态色全部定义为 CSS 变量。
- 亮 / 暗两套完整变量集，通过根节点 `data-theme` 属性切换；“跟随系统”由 `prefers-color-scheme` 媒体查询兜底。
- 默认跟随系统；颜色模式独立持久化到 v2 `settings.json` 的 `colorMode` 字段。
- 强调色独立于颜色模式保存：六个预设、Windows 当前主题色和合法的 `#RRGGBB` 自定义值都通过 CSS 变量作用于主界面；Windows 颜色只在应用启动与设置弹窗打开时读取。
- 当前有效强调色派生为基础色、悬停色、柔和背景、焦点色和可读的 on-accent 前景色，避免组件内散落硬编码颜色。
- 未来主题预设 = 追加预设元数据与颜色派生输入，切换机制不需要动。

## v2 设置契约

设置文件使用版本化结构，颜色模式、强调色和编辑器配置互相独立：

`json
{
  "version": 2,
  "colorMode": "system",
  "accentColor": {
    "kind": "preset",
    "value": "windy-teal"
  },
  "editor": {
    "executable": "",
    "arguments": ["{path}"]
  }
}
`

v1 的 `theme` 与 `editorCommand` 在读取时迁移为上述字段；迁移和后续保存继续使用临时文件写入后替换的原子机制。

## 权衡与后果

**收益**

- 零样式依赖：无运行时样式库、无构建期预处理器，体积与维护成本最小。
- 主题切换即时且全局：改一个属性即换一套色板，无重渲染框架开销。
- 扩展路径清晰：新预设只需增加预设元数据与颜色派生输入，机制不需要动。

**代价**

- 所有样式手写，无组件库现成件；UI 一致性与质量依赖变量纪律（每个颜色 / 间距必须走变量，不得硬编码）。
- CSS 变量无编译期检查，拼错的变量名只能靠人工与视觉走查发现。

**替代方案被拒原因**：样式框架违反硬边界；CSS-in-JS 引入运行时与依赖，与"小巧"目标冲突。
