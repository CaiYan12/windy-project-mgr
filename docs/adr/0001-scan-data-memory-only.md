# ADR 0001: 扫描数据仅存内存，启动全量重扫

- 状态：Accepted（2026-08-25 Grilling Session 决策 D2）
- 决策者：项目负责人 + 执行 Agent

## 背景

应用需要为每个项目展示运行时信息：项目类型、技术栈、Git 状态、最近活动。这些信息有两个特征：

1. **易变**：Git 状态、文件修改时间随时变化，落盘即产生陈旧数据。
2. **采集成本低**：扫描仅做根目录特征文件检查与本地 Git CLI 调用，单项目毫秒到亚秒级。

需要决定：扫描结果是否持久化（引入 TTL、缓存失效、版本迁移），还是每次运行重新扫描。

## 决策

- 扫描结果（`ProjectMetadata`）**仅存前端内存**，不写入任何文件、不做 TTL、不做持久化缓存。
- 启动时立即用持久化的 `projects.json` 渲染卡片骨架，同时并发调用 `scan_project`，结果到达一个填充一个。
- Detail 页复用同一份内存结果；提供手动刷新按钮触发单项目重扫。
- `lastScannedAt` 语义降级为"本次运行内的扫描时刻"。

## 权衡与后果

**收益**

- 零缓存一致性负担：无失效策略、无陈旧数据、无 Schema 迁移。
- 数据永远新鲜：每次启动反映真实磁盘与 Git 状态。
- 持久化模型保持最小（`Project` 仅 8 个字段），`projects.json` 简单可迁移。

**代价**

- 每次启动都重新扫描；项目数量大时启动初期卡片为骨架态（骨架先行已缓解感知延迟）。
- 应用关闭期间的扫描结果不保留（这是预期行为，不是缺陷）。

**扩展点**：若未来项目规模大到重扫不可接受，可引入持久化缓存 + TTL；届时仅增加缓存层，不改扫描管线本身（见原始文档 TODO）。
